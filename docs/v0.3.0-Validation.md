# v0.3.0 验证记录

## 环境与范围

Windows 11、RTX 5070 Ti 16 GB、Python 3.12.10、PyTorch 2.7.1+cu128。沿用此前已验证的模型缓存和独立依赖环境。本次验证已有安装的升级/修复，没有再次执行空系统全新安装；依赖、模型和下载校验来源未变化。

**尚未在物理 6 GB 显卡上验证。** 本次使用 PyTorch `set_per_process_memory_fraction` 设置 4608 MiB（4.5 GiB）分配上限，只约束 PyTorch 分配器，不包括全部驱动/CUDA 上下文开销，也不等价于真实小显存硬件。[PyTorch 官方说明](https://docs.pytorch.org/docs/stable/generated/torch.cuda.memory.set_per_process_memory_fraction.html)

## 实际生成

| 测试 | 模式 | PyTorch 分配峰值 | 保留峰值 | 生成耗时 |
|---|---|---:|---:|---:|
| 25.52 秒歌曲，默认 40 步 | 6 GB 节省显存 | 2079.7 MiB | 2132.0 MiB | 54.3 秒 |
| 222.42 秒完整音乐视频，默认 40 步 | 6 GB 节省显存 | 2104.8 MiB | 2158.0 MiB | 171.0 秒 |
| 37 字中文语音 | 6 GB 节省显存 | 2684.9 MiB | 3058.0 MiB | 40.0 秒 |
| 网页上传 25.52 秒歌曲并点击一键生成 | 自动 → 性能优先 | 2537.9 MiB | 3098.0 MiB | 23.2 秒 |

上述推理均设置 4608 MiB 分配上限。另通过中文网页输入文字并点击一键生成，约 22 秒后得到可试听/下载结果。时间包含模型加载和导出，使用已有缓存，不包括首次下载；不能直接外推其他显卡速度。

保留原参考、模型权重、半精度推理、旋律/音高、默认 40 步和混音。低档使用相同 Demucs 模型在 CPU 分离，扩散模型与声码器分阶段占用 GPU。CPU/GPU 浮点运算差异可能使输出字节不同；不声称不同档位输出逐样本相等。

## 无损与包装

- 完整翻唱 WAV 为 58,857,088 字节；FLAC 为 41,753,746 字节，约小 29.1%。37 字语音 WAV 为 639,556 字节，FLAC 为 413,399 字节，约小 35.4%。
- 用 SoundFile 读取为 int32，验证 WAV/FLAC 的采样率、形状和每个 PCM 样本完全一致。
- ZIP 改为 DEFLATE 9 无损压缩，原始文件字节不变；包内排除模型、运行环境、临时文件和私有配置。压缩率随内容变化。
- 安装器真实隔离夹具测试：只清理 `.runtime/pip-cache`、`.runtime/downloads`，保留 Python 和模型哨兵文件；拒绝跟随目录链接。已有程序的安装修复通过 GPU、音视频工具及三个组件检查。
- 15 个此前登记的原始素材和成品 SHA-256 保持一致。

## 回归与限制

11 项音频/显存策略/任务回归检查通过；3 项 UI 输入路由和 API 兼容检查在 UI 环境通过。原生启动器重新编译，参数传递、ZIP 路径边界和选择性缓存清理自检通过。新 `/generate` 和旧 `/sing`、`/speak` 接口保留。

Docker 镜像未在此次环境构建运行；CPU-only/AMD/Intel GPU 模式未提供。未验证所有 6/8 GB 显卡、驱动版本、600 字最长文本、10 分钟最长输入和后台高显存占用。6 GB 模式仍要求合适的 NVIDIA CUDA 硬件及足够系统内存；不足时应关闭其他 GPU 程序并重试。

安装后体积主要来自原模型和 CUDA 运行库。自动清理安装缓存可避免保留重复下载；没有通过量化、裁剪模型或降低 MP3 码率来缩小体积。Hugging Face 免费页面仍为介绍、试听和下载入口，不提供在线 GPU 推理。
