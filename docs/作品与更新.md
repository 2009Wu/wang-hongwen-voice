# 作品、试听和更新

## 自动保存与作品历史

完成后，MP3、FLAC、WAV、视频和参数记录会自动保存到系统“文档”下的 `Voice Studio作品`，两个工作室各有自己的文件夹。网页中的“作品历史”可以重新载入、播放和下载；“打开作品文件夹”直接打开保存位置。关闭网页、关闭启动器或清理任务临时目录不会删除这些导出文件。

为了支持重试和局部重做，程序另外保存原曲、人声、伴奏、实际参考片段和私有请求。它们保留 7 天，总量上限约 5 GB；新任务完成时先清理较旧的素材，当前任务除外。最终作品和历史记录不会随之删除。素材清理后仍能播放作品，但需要重新上传才能修改。失败或主动停止的任务也会留下可重试记录，前提是已成功保存输入素材。

## 歌曲先试听，再生成整首

上传含有原唱的歌曲，清空文字输入。设置试听起点及 10、15 或 20 秒长度，点击“生成歌曲试听”。满意后点击“沿用这段试听生成整首”，程序使用同一份原曲、参考声音和参数，并把已确认的试听放回对应位置。衔接处有约 80 毫秒淡入淡出。

试听是短片段生成，不是整首任务的断点续算；生成整首仍需要处理整首歌曲。模型、参考素材、精度、音高和默认混音参数保持不变，音色相似度依然取决于参考素材。

## 只重做一段

在“作品历史”选择一条完整翻唱，设置起止秒数，点击“只重做这个区间”。每次最多 120 秒；模型只处理该区间和前后各约半秒衔接素材。原作品保留，新结果另存为一条作品。WAV 在所选区间以外保留原导出样本；区间内部边缘作短淡入淡出。MP3/AAC 为有损重新编码，不能保证压缩字节不变。视频沿用已有视频流，替换音轨，不再压缩画面。

偶发不稳定可以尝试重做，但这不是音色质量或发音的保证。

## 共用模型缓存

Windows 版两个工作室默认共用 `%LOCALAPPDATA%\VoiceStudios\models`。各自启动时会整理旧 `.cache` 中的模型；同一磁盘优先使用硬链接，保留旧路径供旧版使用；已存在且内容完全相同的文件去重。不同磁盘必要时复制，因此不承诺固定节省空间。不会迁移登录令牌或任意用户文件，也不改变权重、精度和生成参数。

两套 Python 运行环境仍独立，作品和收藏不共用。模型迁移可能使首次启动稍慢。磁盘或权限不足会显示错误并保留旧文件，不要自行删除缓存以解决下载问题。

## 更新、回退和诊断

打开“更新与帮助”，点击检查更新。下载通过 ZIP SHA-256 与内部文件清单校验后，点击安装并重启。安装前先停止生成，启动器会关闭服务、替换程序文件，然后重新打开。模型、运行环境、作品和收藏不属于更新替换范围。

每次更新前保存程序备份，可以回退到上一个版本；更新中断时，下次启动会尝试恢复备份。首次从旧版升级到本版，需要下载完整新 ZIP。可以在关闭启动器后覆盖原程序文件夹，保留 `.runtime`；若移动到新目录，仍需修复环境。不要只复制 EXE。

检查和下载更新会连接 GitHub，但不会上传参考声音、歌曲、输入文字或作品。“导出诊断报告”只包含版本、系统、显卡、剩余空间和最近一次错误摘要，不包含录音、文字、作品、收藏或完整运行日志。

## 存放位置

- 作品：系统文档目录 / `Voice Studio作品` / 工作室名称。
- 历史、收藏和可修改素材：`%LOCALAPPDATA%\VoiceStudios` / 项目名称。
- 模型：`%LOCALAPPDATA%\VoiceStudios\models`。
- 更新程序备份：程序目录 / `.runtime/updates/backups`。

开发和测试可用 `VOICE_STUDIO_DATA_HOME`、`VOICE_STUDIO_OUTPUT_HOME`、`MODEL_CACHE` 覆盖位置。Docker/源码部署没有 Windows 启动器时，采用手动更新；常驻部署应挂载持久数据卷。Windows 两个工作室共用缓存不代表可同时运行两个显存密集生成任务。
